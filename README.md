# BENCHCORE

画面は `index.html` だけで構成し、楽天市場の価格取得のみ Vercel Function (`/api/rakuten-prices`) を利用します。認証情報がブラウザへ渡ることはありません。

## 楽天市場の商品対応表を登録する

初期状態の `config/rakuten-products.json` は空です。**商品コードを推測して登録しないでください。** 楽天APIが返す商品コードと商品名を照合し、商品説明・商品ページで対象モデルそのもの（新品・容量・型番・単品／セット内容を含む）だと確認できた商品だけを登録します。

1. 下記の確認スクリプトで楽天APIを検索し、応答に含まれる `itemCode` と `itemName` を確認します。商品ページURLからコードを組み立てないでください。検索結果の先頭や最安値を無条件で採用しないでください。
2. `config/rakuten-products.json` に次の形式で追加します。`modelName` は画面・スプレッドシート上のモデル名と完全一致させ、`category` は `cpu`、`gpu`、`ram` のいずれかにします。

   ```json
   [
     {
       "category": "cpu",
       "modelName": "（BENCHCORE上の完全一致するモデル名）",
       "itemCode": "（API応答の確認済み商品コード）",
       "itemName": "（API応答の確認済み商品名そのまま）",
       "condition": "new"
     }
   ]
   ```

3. 新品のCPU／GPU単品であることを商品説明・商品ページでも確認します。中古・再生品・箱のみ・冷却部品・搭載PC・抱き合わせ商品を除外し、対象ごとに1件を選びます。新品の証拠が不明なものは登録しません。`condition` は人が確認した記録であり、APIの新品判定フィールドではありません。
4. 確認した日時・APIの商品コードと商品名・新品と型番の根拠をPRに記載し、レビューしてからデプロイします。価格更新時にもコード・商品名が完全一致することを検証します。販売ページの商品名が変わった場合は更新失敗として扱い、再確認が必要です。

未登録モデルは従来の参考価格のままで、楽天の価格としては表示されません。登録商品の取得に失敗した場合も参考価格を残しますが、「更新失敗」と表示し、取得日時のない価格を最新価格として扱いません。成功時だけ楽天価格、取得日時、取得元、商品リンクを表示します。

## Vercel の環境変数

Production に次の3項目を設定します（値をリポジトリや `index.html` に書かないでください）。

- `RAKUTEN_APPLICATION_ID`
- `RAKUTEN_ACCESS_KEY`
- `RAKUTEN_AFFILIATE_ID`

ローカルでFunctionを確認する場合は同じ変数を `.env.local` に設定して `vercel dev` を実行します。対応表が空なら認証情報なしでも空の正常レスポンスを返します。

Productionの環境変数はローカルやPreviewには自動で提供されません。Previewで実接続を確認する場合は、Vercelで対象ブランチのPreviewにも環境変数を設定してください。値をチャット・PR・コマンド引数・ログへ貼らないでください。

## 楽天APIの接続仕様と実商品確認

[公式 Item Search API 仕様](https://webservice.rakuten.co.jp/documentation/ichiba-item-search)（2026-09-29確認）に合わせ、次を使用します。

- 接続先: `https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701`
- `applicationId` と `affiliateId` はサーバーからクエリで送信。Access Keyは公式の `accessKey` ヘッダーで送信します。`Authorization: Bearer` は使用しません。
- `format=json&formatVersion=2` を明示し、`items` 配列内の `itemCode`・`itemName`・`itemPrice`・`availability`・`affiliateUrl`／`itemUrl` を処理します。実接続では大文字の `Items` も観測されたため、どちらの配列にも対応します。
- この楽天アプリの許可サイトとして登録された `https://eminem-steel.vercel.app` を `Origin` ヘッダーで送ります。PCで同じ認証値と検索語を使った照会は、Originなしで HTTP 403、付与時に HTTP 200 でした。この確認はProductionでの実行成功を意味しません。登録サイトを変える場合はコード内の `SITE_ORIGIN` も合わせて変更します。
- 購入可能な商品の正の整数円価格だけ採用し、空結果・別商品・商品名変更・不正価格・HTTPエラー・JSON不正は商品単位の更新失敗にします。上流エラー本文、認証付きURL、例外詳細はレスポンスやログへ出しません。

3つの認証変数が安全に設定されたシェルで、次を実行します（Node自体は `.env.local` を自動読込しません）。

```sh
node scripts/verify-rakuten-products.js
```

スクリプトは「Ryzen 9 9950X3D」（検索語 `9950X3D`）と「GeForce RTX 5090」の候補を読み取り専用で照会し、APIの商品コード・商品名・説明・価格・購入可否・公開商品ページURLを出力します。商品ページURLのクエリは除去します。新品の自動認定や対応表への自動登録は行いません。返された候補を上記の手順で照合してください。認証不足や照会失敗の場合は未確認として終了します。

**今回の登録結果: 2モデルとも未登録。** PCからの認証付き照会で候補は取得できましたが、商品の価格・在庫・型番と新品の根拠を購入ページで確定していません。候補を最安値というだけで採用せず、`config/rakuten-products.json` は `[]` を維持しています。PCからの成功はVercel Productionでの実接続成功を証明するものではありません。

## 価格の自動更新（楽天市場）

CPU・GPU の価格は GitHub Actions（`.github/workflows/update-prices.yml`）が毎日 03:37（日本時間）に楽天市場から取得し、`data/rakuten-prices.json` に保存します。サイトはこのファイルを読み込み、取得できた製品は楽天の価格と購入リンクを表示します。取得できなかった製品は参考価格のままです。

### 最初に1回だけ必要な設定

GitHub のリポジトリで **Settings → Secrets and variables → Actions → New repository secret** を開き、次の3つを登録します（値をチャットやコードに貼らないでください）。

- `RAKUTEN_APPLICATION_ID`
- `RAKUTEN_ACCESS_KEY`
- `RAKUTEN_AFFILIATE_ID`

登録後、**Actions → 楽天価格の自動更新 → Run workflow** で手動実行すると、すぐに1回目の取得が走ります。

楽天のアプリ設定の「許可サイト」は `https://eminem-steel.vercel.app` にしてください。旧URLのままでも1回目は旧URLで再試行しますが、ログに更新を促すメッセージが出ます。

### どの商品を採用するか

`scripts/lib/match.js` の規則で、検索結果から次の条件をすべて満たす最安の出品だけを採用します。迷う場合は採用しません。

- 商品名の型番・グレードがモデル名と完全に一致する（例: 「RTX 5070 Ti」を「RTX 5070」として採用しない、VRAM 違いも区別）
- 購入可能で、中古・再生品・PC本体・セット品・付属品を示す語を含まない
- 価格が参考価格の 0.6〜1.8 倍に収まる。参考価格がないモデルは、同条件の出品が3件以上あるときだけ相場付近のものを採用
- メモリ（RAM）は製品名から商品を特定できないため対象外

楽天APIの失敗が多い日はファイルを更新しません。自動取得ファイルの価格は7日を過ぎると最新扱いしません。人が確認して `config/rakuten-products.json` に登録した商品は、自動取得より優先されます。

### スプレッドシートの要確認リスト

同じ実行で `data/sheet-audit.json` も更新します。スプレッドシートのうち、型番や等級が規則と合わないモデル名（例: 「Core i9-14600KF」は正しくは i5）と、価格が未入力で楽天からも取得できなかった行の一覧です。シート自体は書き換えません。

### スプレッドシートへの自動反映（任意）

`gas/sheet-sync.gs` をスプレッドシートの Apps Script に貼り付けると、上の2つのファイルをもとに「価格(円)」列へ楽天価格を書き込み、要確認のセルに色とメモを付けます。手順はファイル冒頭のコメントにあります。まず `benchcorePreview`（シートは変更しない）で内容を確認してください。このスクリプトは実際のシートではまだ動作確認していません。

### シートのモデル名の自動補正

型番の規則から機械的に直せる誤り（「Core i9-14600KF」→「Core i5-14600KF」、「GeForce RTX 6700 XT」→「Radeon RX 6700 XT」など）は、サイト表示時に自動で補正します（`correctModelName`）。補正後に同じ名前になった行や元から重複している行は、スコアが最も高い1件だけ表示します。存在しない型番など直せないものはそのまま表示されるので、要確認リストを見てシートを直してください。

### シートの価格が空・不正な行

サイトは同じ型番の内蔵参考価格で補います。内蔵データにもない型番は「価格不明」と表示し、コスパ計算から外します。

## スプレッドシートの価格と単位

2026-09-29 に `index.html` の `GPU_GAS_URL` が返した元データを確認しました。RTX 5080 は `価格(円): 91`、RX 9070 XT は `価格(円): 98`、RTX 5090 は `価格(円): 549800` でした。最初の2件は取得時点ですでに小さい数値であり、万円・千円という根拠はありません。既存の `toNum` は数値をそのまま返すため、この2件は変換時の桁落ちではありません。文字列では単位を削除し `parseInt` するため、別途「9.8万円」なども壊れる問題がありました。

確認できたのはシートを配信する Apps Script のJSONです。元シートのセル書式・数式はこの応答には含まれず、正しい価格は確定していません。CPUの応答も確認し、RAMの配信先はHTTP 403でした。再現用にGPUの実際の4行を `test/fixtures/gpu-price-source.json` に保存しています。

- `価格(円)` は円、`価格(万円)` は万円として解釈します。全角括弧・数字も対応します。
- 単位のない列 `価格` / `price` では `98,000円`、`¥98,000`、`9.8万円` のように値に単位を記載してください。裸の数値から単位は推測しません。
- セルと列の単位が矛盾する場合、複数の価格列、空欄、ゼロ、負数、範囲や注釈を含む値、不正な桁区切り、円未満の端数は採用しません。
- シート由来のCPU・GPU・RAM価格は、円換算後1,000円未満も要確認とします。これは今回の91・98などを誤って採用しないための保守的な入力下限であり、相場判定や倍率推定ではありません。実際に1,000円未満の商品を扱う場合は価格と単位を確認し、この方針を見直してください。確認済み楽天API価格や内蔵の円データにはこの下限を適用しません。
- 不明・不正な価格は `null` として保持し「価格不明」と表示します。性能一覧は維持し、コスパ計算・コスパ順の一覧・バッジ・予算指定の対象から除外します。価格順では不明を常に最後に置きます。

元シートを修正する際は商品価格の根拠を確認して、円の整数値を `価格(円)` に入力するか、列を `価格(万円)` にして万円の値を入力してください。91や98を一律に掛けたり、シートのコスパ値から価格を逆算したりしないでください。サイト側の元データキャッシュは最長10分です。

回帰テストは外部通信なしで、実際の元データ、円・万円変換、不正値、CPU/GPU/RAMの表示・コスパ順の両方向を確認します。`npm test` は `node --test` を実行します。
